# 3D 预览：把切好的图贴回真实屏体

1.0 只出图；2.0 多一个 3D 视口，让非 CG 的人**直接看到这几张图贴到现场屏体上是什么样**。
前提是能拿到一份和投影相机同一套坐标的屏体模型（通常从 Houdini/Blender 导 GLB）。

## 先证明一件事：模型的 UV 就是切图的像素栅格

动手写网页之前，**必须先做这个数值验证**，否则后面所有对齐都是猜：

用 GLB 里的相机把每个 mesh 顶点投影到成片帧（几何单位与相机自洽），
再拿该顶点 UV 去查坐标图（`raw/u_*.png`）得到 DCC 预测的位置，逐顶点比：

```
err = |proj(vertex) - (u(uv)·W, (1-v(uv))·H)|      # 覆盖区域内取平均
```

实测能到 **0.4–0.7 px / 6000 帧**。这说明三件事同时成立：

1. GLB 的相机 == DCC 的投影相机（位置、朝向、FOV、画幅比）；
2. mesh 的 `TEXCOORD_0` 与切图 PNG 的像素栅格同向同尺度；
3. **切图可以直接当贴图贴上去，不需要重新烘 UV，也不需要缩放补偿。**

顺便把每块屏的面板覆盖度也读出来（`mask_*.png` 均值）——那是 3D 视口里必然出现的黑边，
先把话说清楚，免得被当成 bug。

FOV 与画幅比要一起定：用 `yfov` 作**垂直**视角、画幅比取成片帧（如 6000/1538），
观众机位才和 DCC 构图一致。渲染时给个"按成片门框取景"的开关（letterbox），自由视角再放开。

## 场景 GLB 的处理

导出器常留下**场景外孤立节点**（重复的网格、多余的相机），先剔掉再量化：

```bash
python scripts/glb_web.py <场景.glb> --out scene --set <集合目录>
```

* POSITION → normalized uint16，TEXCOORD_0 → uint16，索引 → uint16/uint32，
  丢掉 NORMAL/TANGENT（屏体自发光，用不上）；
* 量化后的真实尺寸/偏移**写进节点矩阵**（`世界坐标 = pmin + q/65535 × span`），
  不依赖加载器怎么理解 `KHR_mesh_quantization`；
* 实测 4.95 MB → 0.82 MB（17%），量化误差 7.7e-6 场景单位 ≈ 0.046 px / 6000 帧；
* 刻意**不用 Draco**：单文件网页不想再背解码器。

脚本结尾会**把刚写出的文件重读一遍**核对相机位姿与网格包围盒——这一步抓出过
"矩阵存反了"的致命 bug（见下）。别省。

## 网页侧

模板 `assets/page_template_v2.html` 内置一个只吃这个子集的 glTF 解析器 + WebGL2 渲染，
不引任何第三方库。要点：

* **自发光**画屏体（不光照），非屏体网格给平灰；屏体**关背面剔除**（模型常是双面壳）；
* 观众机位直接取相机节点的世界矩阵求逆；自由视角用轨道相机，从观众机位**无损接管**
  （用当前眼位反推 yaw/pitch/dist，拖一下不会跳）；
* 贴图从切图 canvas 降到长边 4096 再上传（四张全分辨率要 ~115 MB 显存），
  并 `generateMipmap`——6600 宽的屏在画面上只占几百像素，不做 mipmap 全是噪点；
* 每块屏可显隐、可一键把镜头对准它；整页保持单文件、离线、`file://` 双击可用。

## 验收

1. **CPU 黄金对照**（`scripts/verify_3d_cpu.py`）：在 Python 里用同一套切图 + 软件光栅化
   渲一帧观众机位，同时给出"重建 vs 原图"的误差。
   * 这一条本身就是方案能否成立的证据：实测 3000×769 全分辨率贴图时平均 5.0/255（p50=2），
     也就是说**四块屏从观众机位看回去，确实还原出了原画面**。
2. **无头浏览器**（`scripts/browser_test_v2.py`）：网页视口和 CPU 对照比。
   * 逐像素比会被采样方式差异主导（GPU 双线性+mipmap vs CPU 最近邻，高频素材上能差 30/255），
     所以判定用**降 8 倍后的结构比对**（实测 2.2/255，门槛 3）+ **重建 vs 原图**（网页应不差于 CPU 对照）+ 
     **素材上下翻转的敏感度对照**（实测 10.6 倍，门槛 3 倍）——最后这条专门防"v 轴写反"这类静默错误。
3. 人眼：`scripts/shot_page.mjs` 用 CDP 抓整页截图（观众机位 + 环绕视角各一张）。

## 坑（都是亲身踩的）

* **glTF 矩阵是列主序**。读 1 维数组要用 `reshape(4,4,order="F")`，
  但对**已经是 4×4 的数组**再用同样写法不会转置（同形状 reshape 是恒等），
  写出去必须用 `m.flatten(order="F")`。存反了的表现是：相机跑到原点、画面全空。
* **量化顶点自己算包围盒要除以 65535**。`normalized` 标志只对 GPU 生效；
  用原始 0..65535 算场景中心会把中心算到几万米外，near/far 跟着飞走，画面全空
  （而且**观众机位也一起空**，因为 near/far 是按场景中心算的）。
* **`file://` 页面往 `http://127.0.0.1` POST 图片会先发跨域预检**，
  验收服务器必须实现 `do_OPTIONS`，否则 file:// 模式静默卡死（http 模式看不出来）。
* **别用 `msedge --screenshot --virtual-time-budget` 抓这种页面**：虚拟时钟会抢在
  `createImageBitmap`/`toBlob` 这些真实异步任务前面跑完，截到半成品。用 CDP。
* 视口贴图上传的是**切图 canvas**，不是 PNG blob——省一次编解码，也避免重复贴图。
